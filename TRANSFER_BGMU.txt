ПОЛНЫЙ ПРОЕКТ ДЛЯ НОВОГО РЕПОЗИТОРИЯ

В архиве полный текущий код обоих ботов, зависимости с закреплёнными версиями,
тесты, README, примеры переменных окружения и проверки GitHub Actions.
Включены последние изменения: только группы в ежедневной загрузке,
4 параллельных запроса с интервалом 0,25 секунды между началами запросов,
лимит обновления 15 минут, дни недели и виды занятий в расписании,
открытый журнал с изолированным модулем предупреждения.
Предупреждение отправляется в чат перед записью. При ошибке его модуля
запись блокируется; расписание остаётся доступным.

1. НОВЫЙ РЕПОЗИТОРИЙ

Распакуйте ZIP. Загрузите РАСПАКОВАННЫЕ файлы в новый репозиторий.
Не загружайте один ZIP вместо файлов проекта.
main.py, requirements.txt, pyproject.toml и uv.lock должны быть в корне репозитория,
рядом с папками bgmu_bot и restricted_bot.
Загрузите также .gitignore, .python-version и .github, если они скрыты проводником.
Код можно разместить в ветке main. На хостинге выберите ту же ветку.
История старого Git-репозитория в архив не включена.

2. ЗАПУСК НА BOTHOST

Python: 3.12
Установка зависимостей:
python -m pip install --require-hashes -r requirements.txt
Команда запуска:
python main.py

Переменные окружения задаются в настройках хостинга, не в GitHub:
TELEGRAM_BOT_TOKEN — токен общего бота;
RESTRICTED_BOT_TOKEN — токен исходного бота, если нужны оба бота;
ADMIN_USERNAME=Timur0_15
BGMU_DATA_DIR=.data
DATA_DIR=.data/restricted
BGMU_PROXY_URL — только если вашему хостингу действительно нужен прокси.

Пример без секретов находится в .env.example. Он не загружает переменные
автоматически в общий бот: задайте их через настройки хостинга.
Оригинальный бот ограничен прежним ботом и прежним управляемым чатом,
как и в предыдущей версии. Перенос репозитория не меняет эти ограничения.
Если нужен только общий бот, не задавайте RESTRICTED_BOT_TOKEN.

3. ПОЛЬЗОВАТЕЛИ И ДАННЫЕ

В этом архиве НЕТ действующих пользователей, привязок, журналов чатов,
ДЗ, токенов и паролей: они находятся на вашем хостинге, а не в исходном коде.
Чтобы сохранить их, перенесите папку данных отдельно через файловый менеджер
хостинга. Никогда не публикуйте её в GitHub.

Пути по умолчанию:
.data/preferences.sqlite3 — пользователи, группы и настройки общего бота;
.data/schedule.sqlite3 — ежедневная база расписания;
.data/restricted/bot_data.db — ДЗ и настройки исходного бота;
.data/backups/ и .data/restricted/backups/ — резервные копии;
.data/chat-journals/ — TXT-журналы и состояние предупреждений.

Если BGMU_DATA_DIR или DATA_DIR заданы иначе, сохраняйте именно эти каталоги.
Перед переносом скачайте резервные копии из админ-панели.
Для окончательного копирования актуальных файлов данных остановите старый
процесс, сохраните папку данных и поместите её в новый проект с теми же путями.
Не запускайте одновременно два экземпляра с одними и теми же токенами:
они будут конфликтовать при получении обновлений Telegram.
Если хостинг при обновлении репозитория пересоздаёт рабочую папку,
обеспечьте постоянное хранение каталога данных или восстановите его до запуска.

4. ПРОВЕРКИ

Включённые GitHub Actions проверяют код и сайт, ботов Telegram не запускают.
Их push-фильтры сохранены от исходного репозитория и ориентированы на старые
ветки codex. В новом репозитории доступен ручной запуск через Actions -> Run workflow.
Чтобы проверки запускались автоматически в main, отдельно измените branches
в файлах .github/workflows. Для сохранения отчётов нужна запись Contents.
Исторические JSON-отчёты в verification/ не подтверждают доступ с вашего хостинга.
